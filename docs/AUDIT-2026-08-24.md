# MK-OrbitControl Audit — 2026-08-24

## Scope

Repository structure, Git hygiene, SwiftUI accessibility and rendering, Swift state and command paths, Python bridge validation, MIDI and hotkey lifecycle, setup and distribution scripts, documentation, tests, signing, and the installed local runtime.

## Baseline

- Swift tests: 11 passed before cleanup.
- Python bridge tests: 7 passed before cleanup.
- Installed build 33 launched with the authenticated bridge listening only on `127.0.0.1:17580`.
- Widget support had already been removed; no extension or widget command port remained.

## Findings and Actions

### P1 — Safety

- Global hotkey volume fallback used raw `0` when channel state was missing. In this protocol, raw `0` is 0 dB (maximum), while raw `96` is silence. The fallback now fails quiet and has a regression test.

### P1 — Repository hygiene

- `dist-bundled/` was ignored but still contained 930 tracked generated files. It is now removed from version control while remaining available as a local ignored build output.
- Five unused duplicate icon files were removed. `Config/AppIcon.icns` is the single canonical icon.

### P2 — Reliability and maintainability

- Swift source is grouped by Application, Domain, Infrastructure, Input, Services, and UI responsibility.
- Duplicate global hotkey bindings now replace the earlier action instead of triggering ambiguous commands.
- CoreMIDI source connections are reconciled when devices change and disposed with the manager.
- Invalid persisted MIDI channel/CC mappings are discarded during loading.
- Existing bridge-token and application-support permissions are repaired to owner-only modes.
- The distribution script now stops on unhandled command failures.
- Popover animation respects Reduce Motion and duplicate fallback MIDI manager creation was removed.

### P2 — Accessibility and documentation

- Unlabelled settings controls now have explicit accessibility names.
- UI smoke tests are deterministic and cover both full and mini layouts.
- Installation documentation and historical planning were organised under `docs/`.
- Generated screenshots and repository structure documentation were refreshed.

## Follow-up Polish

- Added configurable 1, 2, 3, or 6 dB step controls beside the main dial. The same preference now drives keyboard, VoiceOver, and global-hotkey adjustments.
- The preferred output, compact/full layout, night-mode cap, and volume step now survive relaunches and reject invalid persisted values.
- Step controls expose accessible names and disabled limit states while retaining the existing 0 dB and night-mode safety clamps.
- Persisted MIDI and global-hotkey mappings now reconcile duplicate physical bindings so one gesture resolves to one action.

## Remaining Risks

- Hardware command behaviour still requires controlled validation on every supported Antelope model; source, build, and socket verification cannot replace a physical audio test.
- The Swift state reader chooses an installed report format independently from the Python bridge. Multi-panel Antelope installations remain a compatibility risk and need hardware-backed protocol work.
- Python 3.8 is required by the extracted Antelope bytecode ABI and is end-of-life. The runtime should remain minimal, local-only, and replaced if Antelope moves to a supported Python ABI.
- Developer ID signing and notarisation are separate release gates. Local ad-hoc signing does not establish public distribution readiness.
- Theme contrast is visually reasonable in the primary themes but has not been exhaustively measured across every theme and transparency combination.
